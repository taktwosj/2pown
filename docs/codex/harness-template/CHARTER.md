# Harness Charter (Template)

## Goal

Increase user trust, verification quality, and change safety by running work through a Planner / Builder / Evaluator loop.

## Scope

- One project at a time
- One sprint at a time
- Local-first implementation and verification

## Non-goals

- Silent broad refactors
- Unapproved API contract changes
- Unapproved deployment or push

## Definition of Done

The user can verify what changed, how it was tested, what risks remain, and whether the sprint passed.

Harness completion requires:

1. Current sprint implemented or documented as planned
2. QA or manual checks recorded
3. `Documentation.md` updated
4. `STATUS REPORT` emitted
