# 2POW Codex 사용 체크리스트

이 체크리스트는 `2POW`에서 실제로 작업한 흐름을 기준으로 만든 운영 점검표다.

## 10가지 체크
- [ ] 요청을 `대화`가 아니라 `파일 산출물` 기준으로 말한다.
- [ ] 수정 범위를 폴더나 파일 경로로 제한한다.
- [ ] 원본 화면보다 원본 코드나 원본 데이터 파일을 먼저 준다.
- [ ] 최신 정보가 필요한 내용은 따로 검증 대상으로 분리한다.
- [ ] 한 번에 하나의 목적만 준다. 예: 버그 수정, 데이터 정제, 문서화.
- [ ] 끝나면 검증 명령이나 확인 방법을 같이 요구한다.
- [ ] 결과 보고는 `무엇을 바꿨는지 / 어떻게 검증했는지 / 남은 리스크` 순으로 받는다.
- [ ] 반복 작업은 대화로 끝내지 않고 스크립트나 문서로 남긴다.
- [ ] 백업과 버전관리를 구분한다. OneDrive는 백업이고, Git은 변경 이력 관리다.
- [ ] 실패 사례와 예외 케이스를 다음 작업에 재사용할 수 있게 기록한다.

## 현재 2POW 기준 평가
- 잘하고 있는 점: 실제 산출물을 남기고 있다.
- 잘하고 있는 점: 문제를 찾으면 원인까지 파고들고 재검증한다.
- 잘하고 있는 점: 반복 작업을 스크립트와 실행 문서로 바꾸고 있다.
- 개선할 점: 작업 범위를 더 좁게 주면 속도와 정확도가 더 올라간다.
- 개선할 점: 원본 파일 기준 요청을 더 늘리면 진단이 빨라진다.
- 개선할 점: root repo와 nested repo를 구분해서 `fetch/pull` preflight를 먼저 보는 습관이 더 필요하다.

## 2POW에서 특히 지키면 좋은 습관
- `myhome` 작업은 입력 데이터, 생성물, 보고서를 구분해서 요청한다.
- `admin`과 `ivwith` 작업은 `myhome`과 섞지 말고 별도 작업으로 분리한다.
- 대용량 CSV를 다시 만들 때는 코드 수정과 결과 파일 재생성을 구분해서 보고받는다.
- 화면 문제는 가능하면 렌더 결과 HTML보다 원본 HTML/JS 파일 기준으로 맡긴다.
